# 桌面版分析体验重构设计

日期：2026-07-11  
状态：用户已通过交互草图确认主方向

## 1. 目标与范围

本轮重构解决四个核心问题：

1. “今日”页的时间结构难以比较，任务分布、应用排行和时间分布之间缺少稳定层级。
2. 应用名称和图标与 Windows 本机状态不一致，例如旧名称 Codex 与新名称 ChatGPT 混用。
3. 当前趋势页只能展示简单的 7 天总量，不能支持月度、自定义区间、区间对比和可靠评价。
4. 当前工作流页只是活动片段列表，不能说明项目或任务究竟推进了什么。

本轮不修改活动采集、空闲回填、浏览器历史采集和原子分类定义。动态壁纸、知识图谱和声音交互也不属于本轮范围。

## 2. 已确认的产品决策

- “今日”主分析区固定为三栏：`任务分布 / 应用排行 / 时间分布`。
- 时间分布使用 12 个两小时桶：`00-02` 到 `22-24`。
- 两小时桶的纵轴使用 `0 / 60 / 120 min`，避免沿用一小时桶的 60 分钟上限造成误导。
- 时间图默认比较 `活跃` 与 `学习`，并允许勾选其他正式分类参与比较。
- 行动队列从首页移除；专注计时器降级为顶部可选小工具，不再占据完整板块。
- “今日工作画像”改为 `AI 分析`，包含 `今日工作画像` 与 `评价和建议` 两个独立区域。
- 工作流保留，但重新定义为项目推进台：`项目 -> 任务 -> 证据 -> 待复核`。
- 趋势页支持近 7 天、本月和自定义日期区间，并默认与前一个等长区间比较。

## 3. 今日页设计

### 3.1 阅读顺序

1. 六项核心指标：总监测、活跃、学习、空闲、切换负荷、最长专注。
2. 三栏主分析区：任务分布、应用排行、时间分布。
3. 活动时间线。
4. 目标与实际产出。
5. AI 分析。

行动队列被删除。紧凑专注入口放入顶部工具区，默认只显示一个计时图标；用户打开后选择目标和 25/45/60 分钟。

### 3.2 任务分布

- 左侧显示约 140-160px 的圆环，中心显示总监测时长。
- 右侧显示紧凑分类列表，包括名称、时长、百分比和短进度条。
- 悬停圆环扇区或列表行时高亮同一分类，浮层显示小时/分钟和百分比。
- 点击扇区或列表行时跳转到活动时间线，并按分类筛选。
- 图表选中只改变高亮和筛选，不重新创建整个 ECharts 实例。

### 3.3 应用排行与本机身份

- 结构与任务分布一致：左侧圆环、右侧紧凑排行。
- 应用时长只累计前台非空闲片段。
- 新增统一的 `AppIdentity`：`canonicalId`、`displayName`、`executablePath`、`productName`、`aliases`、`iconCacheKey`。
- 显示名称优先级为：用户覆盖 > 可执行文件 ProductName > 内置别名 > 原始进程名。
- 不将所有 Code/Codex 字符串直接改为 ChatGPT。仅当可执行路径或 Windows 产品元数据能确认对应新 ChatGPT 桌面应用时更新名称。
- 图标优先从本机 EXE 提取并缓存；提取失败时使用内置品牌图标；仍失败时使用通用应用图标。
- 应用排行和活动时间线共用同一个 `AppIcon` 组件与身份解析结果。

### 3.4 两小时时间分布

- 12 个桶来自现有 `TimeBucketMetric`，跨边界片段按真实重叠时长切分。
- 默认显示活跃和学习两组并列柱。学习是活跃的子集，但作为独立比较序列，不与活跃相加。
- 用户可勾选搜索/调研、视频信息输入、文字信息输入、游戏、社交软件、创作开发、文件整理和空闲。
- 少量序列采用并列柱；选择较多分类时图表保持 12 个桶不变，并缩窄柱宽。图例支持一键恢复默认。
- 悬停任何色块时显示：时段、分类、时长、占两小时窗口比例、占该桶监测时间比例。
- 点击色块时按 `timeBucket + series/category` 筛选活动时间线，并将时间线标题滚动到视口中上部。
- 空桶保留稳定横坐标，不引发布局跳动。

### 3.5 时间线钻取

- 所有指标卡、任务分类、应用排行和时间柱共用一个 `TimelineFilter`。
- 支持 `all / active / idle / learning / category / app / segment / timeBucket`。
- 跳转使用固定顶栏高度加 20-32px 的偏移，使时间线标题和第一条记录同时可见。
- 当前筛选以可清除的筛选标签显示。

## 4. AI 分析设计

### 4.1 两个输出区域

- `今日工作画像`：描述时间结构、主要活动模式、目标相关工作、专注与切换特征。
- `评价和建议`：评价目标推进、指出有统计证据的问题，并给出下一工作日可执行建议。

系统不分析心情，也不基于短期数据评价人格或能力。

### 4.2 先统计、后 AI

Rust 端先生成结构化 `DailyAnalysisEvidence`：

- 今日目标、预期产出和实际产出。
- 总监测、活跃、学习、空闲、分类占比。
- 两小时桶、主要应用、最长专注、切换负荷。
- 与目标匹配的项目/任务片段和证据。
- 分类覆盖率、低置信记录、浏览器摘要可用性。

AI 只接收脱敏后的结构化证据和有限摘要，不接收完整数据库或全部原始窗口日志。在线时生成 AI 结果；离线时显示本地统计画像，并将 AI 任务写入现有补算队列。网络恢复后自动补算，结果按日期和证据哈希去重。

## 5. 趋势页设计

### 5.1 区间控制

- 快捷范围：近 7 天、本月。
- 自定义范围：起始日期与结束日期，限制为有效且不颠倒的日期。
- 默认比较前一个等长区间，例如选择 7 天时比较此前 7 天。

### 5.2 页面结构

1. 区间 KPI：日均活跃、日均学习、目标完成率、专注稳定性、娱乐占比、分类可信度。
2. 趋势主图：逐日活跃、学习、创作开发，可切换分类。
3. 学习日历：按天显示学习时长和记录完整度。
4. 结构变化：任务分类、主要应用、项目推进的区间占比。
5. 对比结论：与前一区间的变化、稳定改善和风险指标。
6. AI 区间评价：总结变化是否持续、证据是否充分、下一阶段建议。

### 5.3 数据接口

将现有 `get_trends(start_ms, end_ms)` 扩展为返回聚合后的 `TrendPayload`，包括逐日指标、区间汇总、前一区间对比和数据质量。前端不再为每项指标重复遍历完整时间线。

## 6. 工作流页设计

工作流页更名为“项目推进台”，采用三栏结构：

1. 左栏：项目列表，显示今日时长、任务数、最近推进和趋势。
2. 中栏：选中项目的任务推进账本，按时间展示任务、证据、产出和置信度。
3. 右栏：仅展示需要用户判断的低置信项目归属、任务合并和应用别名建议。

AI 将连续活动片段、浏览器访问、今日目标和窗口标题合并为 `WorkEvidence`，再归入项目和任务。用户确认后生成高优先级规则。页面不再重复展示普通时间线；没有项目数据时显示创建第一个项目或让 AI 从今天活动提出项目草稿。

## 7. 前端边界

当前 `App.tsx` 体积过大。本轮只做与目标相关的拆分：

- `TodayView`
- `DistributionPanel`
- `AppRankingPanel`
- `TimeDistributionPanel`
- `TimelinePanel`
- `AiAnalysisPanel`
- `TrendsView`
- `ProjectLedgerView`
- `AppIcon`

视图组件只接收已经聚合的 DTO；时间计算、身份解析和区间对比分别位于独立的 `metrics`、`app-identity` 和 `trends` 模块。

## 8. 错误与降级

- 本机图标提取失败：回退内置图标或通用图标，不阻塞页面。
- AI 不可用：保留本地统计画像，显示“等待联网补算”，不隐藏数据。
- 自定义区间无记录：显示空状态和实际查询范围，不生成虚假评价。
- 分类置信度不足：结果可以暂时显示，但必须标记为待复核并降低 AI 结论可信度。
- 趋势查询过大：使用数据库聚合和日期索引，不将数月原始片段一次性传给前端。

## 9. 验收测试

- 12 个两小时桶覆盖完整 24 小时，桶总量与当日汇总一致。
- 每个桶的学习时长不大于活跃时长；跨桶片段按重叠时长准确拆分。
- 默认只勾选活跃与学习；分类选择、悬停浮层和点击钻取正确。
- 三栏在 1366px 以上并排；窄屏依次降为两栏和单栏，无横向页面溢出。
- 时间线钻取后标题和第一条记录都位于可视区，不被固定顶栏遮挡。
- 应用排行与时间线使用相同名称和图标；未知应用稳定回退。
- 行动队列不再出现；专注工具只在顶部可选入口中出现。
- AI 分析包含两个区域，离线时仍显示本地统计结果。
- 趋势页支持 7 天、月度和自定义范围，并正确比较前一等长区间。
- 工作流页能展示项目、任务、证据和待复核闭环。
- 前端测试、Rust 测试、生产构建和 Tauri smoke test 通过。

## 10. 实施顺序

1. 稳定 DTO、两小时图表和统一时间线钻取。
2. 重构任务分布、应用排行和本机应用身份。
3. 移除行动队列，将专注功能收纳到顶部。
4. 实现结构化证据和 AI 分析双区域。
5. 重做趋势页及区间聚合接口。
6. 将工作流重做为项目推进台。
7. 完成响应式、无障碍、离线降级和全套验证。
